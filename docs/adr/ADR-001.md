# ADR-001: Arquitectura Hexagonal para aislar el dominio

## Estado

Aceptado - 2026-05-19

## Contexto

El sistema de pedidos debe poder cambiar sus detalles tecnicos sin afectar las reglas centrales del negocio. En el proyecto existen responsabilidades distintas: crear pedidos, procesarlos segun su tipo, guardar su estado y publicar notificaciones cuando el pedido queda procesado.

Si el dominio dependiera directamente de controladores REST, persistencia, Spring o clases de infraestructura, cada cambio tecnico podria obligar a modificar las clases de negocio. Eso haria mas dificil probar el dominio de forma aislada y tambien aumentaria el riesgo de romper reglas de negocio al cambiar una tecnologia externa.

## Decision

Se adopta una arquitectura hexagonal. El dominio queda en el centro y define sus puertos como interfaces en `com.empresa.pedidos.dominio.puertos`. Los adaptadores y la infraestructura se ubican por fuera y dependen del dominio, no al contrario.

La fachada de pedidos actua como punto de entrada de la aplicacion para coordinar el caso de uso. El adaptador REST llama a la fachada, los procesadores implementan el puerto `ProcesadorPedido`, y la infraestructura implementa puertos como `RepositorioPedidos` y `PublicadorEventos`.

Esta decision se protege con reglas ArchUnit que impiden dependencias del dominio hacia `infraestructura`, `adaptadores`, JPA o Spring Mail.

## Consecuencias

Positivas:

- El dominio puede probarse y evolucionar sin levantar un contenedor Spring.
- Cambiar la persistencia en memoria por una base de datos requiere crear o reemplazar un adaptador, no modificar entidades de dominio.
- Las reglas arquitectonicas quedan verificadas automaticamente en pruebas y en GitHub Actions.

Negativas:

- La estructura inicial tiene mas paquetes e interfaces que una aplicacion MVC pequena.
- Un desarrollador nuevo debe entender la direccion correcta de dependencias antes de agregar nuevas clases.
- Algunas reglas ArchUnit deben mantenerse actualizadas si se agregan nuevos adaptadores o tecnologias permitidas.
